# SPEC

## §G GOAL
Daemon keeps CWD identical across static peer set: inotify detects change → ZMQ PUB/SUB announces → libtorrent moves bytes. Periodic reconcile repairs dropped announcements ∴ convergence ⊥ rest on control-plane delivery.

- Control plane ZMQ, data plane BitTorrent v2. ⊥ custom transport.
- DHT ⊥ public router — `dht_bootstrap_nodes` set empty (§V.61). Peer set static & ∀ `create` carry the sender libtorrent endpoint, `add_dht_node` @ receipt (§V.8, §R.2) ∴ the swarm seeds its own DHT & a router adds ⊥. Load-bearing, ⊥ incidental: the default is a host on the internet, unreachable here (§R.6), & restoring it re-adds ~1 s to ∀ stop (§R.25) & re-joins syncfs to the global DHT. ∴ syncfs ⊥ reachable from, ⊥ visible to, the public DHT.
- Control plane ⊥ reliable. ZMQ PUB drop, silently, ∀ msg whose subscriber queue is full & ∀ msg published before that subscriber finished connecting (slow joiner). ⊥ ack, ⊥ retransmit. Loss repaired by periodic reconcile (§I `state`/`digest`) ∴ 1 dropped `create` costs ≤ 1 repair round, ⊥ permanent. `sndhwm`/`rcvhwm` raise the ceiling (§V.40) & shrink the window, ⊥ remove it. ∀ writer waiting for ∀ peer subscription before first write (§B.9) = pre-§V.41 mitigation, drops when reconcile lands (§T.50).
- ⊥ central server. Peer set static, read from file @ startup.
- Sync scope = CWD recursive. Regular non-symlink files only.
- File update semantics = last write wins. Order = origin wall clock — mtime @ the node that wrote the file, ⊥ @ the node that received it. Newest `create` for a path replaces whatever torrent held that path. ⊥ conflict resolution, ⊥ content history, ⊥ merge. Per-path delete marker (tombstone, §V.37) allowed: absence state, ⊥ version history.
- Ordering ties: create vs create → lower info hash wins. delete vs create → create wins ∴ the unresolvable case biases toward keeping data — a wrongly-kept file is visible & re-deletable, a wrongly-deleted one is gone. Tie-break ! be computable from the message alone — neither `create` nor `remove` carries a sender address (§I) ∴ ⊥ tie-break on peer address.
- Peers ! run synchronized clocks, skew ≪ reconcile period. Ordering rests on origin wall clock ∴ skew > period ? lose a genuine delete | a genuine create. Same risk class last-write-wins already accepts.
- Reconcile = hash-first, gated on quiescence. `state` (root hash) published every 5 s while quiescent; quiescent == ⊥ change to sync dir for 10 s & ∀ torrent seeding | finished. ∀ change resets the window — local edit & libtorrent write alike, else a receiver mid-transfer publishes a hash of a half-populated tree. Ceiling: publish `state` every 60 s regardless ∴ under continuous write load a dropped announcement repairs within 60 s, ⊥ never. `digest` (full state) published only on hash mismatch ∴ idle cost ~32 B per node per period. Under real divergence only the lacking node sends, & to 1 peer ∴ the burst is O(M) per lagging node per round, ⊥ O(N·M) (§V.56, §V.59). Constants: reconcile period 5 s, quiescence window 10 s, ceiling 60 s.
- Constants, ⊥ configurable: reconcile period 5 s, quiescence window 10 s, `state` ceiling 60 s, tombstone TTL 1 h. Repair suppression window ⊥ a constant — scales with gap count (§V.51). Period & TTL decoupled — period bounds convergence latency, TTL bounds tolerated peer downtime. Coupling them (TTL = 10× period) would set the downtime budget @ 50 s, which a `podman-compose` restart exceeds.
- Tombstones in memory ∴ lost on restart. Accepted limit: node returning with a deleted file resurrects it if it was down > TTL, | if ∀ peer holding that tombstone restarted meanwhile. Persisting them needs a state dir outside CWD — anything inside CWD is itself synced — ∴ a new §I arg & its error paths, rejected as out of proportion to the gap.
- Repair *chosen* pull-wise, *delivered* broadcast, & ⊥ elected. The node with the gap picks 1 peer per round & addresses its `digest` there; that peer alone answers, & its answer is a broadcast `create` so ∀ node loads the torrent & seeds it (§V.56, §V.58, §V.59, §V.60). Addressing the digest cuts the bookkeeping fan-out; broadcasting the repair keeps the swarm. Gap survives the round → next round draws another peer ∴ a wedged peer costs 1 round & ⊥ failure detector needed (§R.16, §R.20, §R.21). Randomized delay + suppression (§V.51) retired: it existed only because PUB/SUB had no request path & a broadcast repair let ∀ holder answer at once — addressing the digest removes both. Deterministic assignment (modulo over the holder set) rejected: it needs ∀ node to agree on that set over a plane that drops ∴ its failure case is 0 senders, silent & permanent, where randomization's was duplicates (§R.15, §R.17, §R.18).
- clang-tidy `Checks: "*"` minus listed, `-warnings-as-errors=*` (from `myproject_WARNINGS_AS_ERRORS` ON, `cmake/StaticAnalyzers.cmake:71`). ∴ ⊥ Boost.Asio in own sources — `boost/asio/io_context.hpp` trips `misc-header-include-cycle`.
- googletest added inside `setup_test_dependencies()` with `CMAKE_CXX_CLANG_TIDY`/`CPPCHECK` cleared @ function scope ∴ own sources exempt, `tests/` ⊥ exempt.
- Tests: GoogleTest (unit) + pytest ≥ 9.0.0, pytest-benchmark ≥ 5.2.3, pytest-repeat ≥ 0.9.4 (integration, performance), Python ≥ 3.13, poetry. Build & test run in `localhost/syncfs-env` (`fedora:44`, clang + ninja + ccache + lld) via podman (`Makefile`).
- Ceiling = peer connections, ⊥ file descriptors. Peak concurrent connections ≈ 0.70 × M files × (N−1) peers @ N ≥ 5 (§R.27) ∴ §T.42's "1 connection per torrent per peer" holds, @ ~70% of it. `connections_limit` -1 sets that ceiling to soft `RLIMIT_NOFILE` **verbatim** — ⊥ the 80%−20 libtorrent applies to a positive value (§R.26) ∴ ∀ run ! size `RLIMIT_NOFILE` ≥ 0.70·M·(N−1), as a *connection* budget & ⊥ as an fd count. fds ⊥ the binding term: uTP is on by default & multiplexes ∀ connection over the listen socket's 1 UDP fd ∴ measured fds stay ≤ 184 @ 2803 connections; only TCP peers cost 1 fd each. Headroom @ the 1048576 the container gives ≈ 1.5e6 torrent-peer pairs — 5 nodes × 2541 files (§B.9) draws ~7.1e3 ∴ 2 orders clear. ⊥ ulimit set in `Containerfile`, `Containerfile.run`, `compose.yaml` ∴ the ceiling is whatever the runtime hands the process, ⊥ anything syncfs states.

## §I INTERFACES
- cmd: `syncfs <peers file> <listen address>` → syncs CWD. args < 3 → usage on stdout, `EXIT_FAILURE`. usage line 1 = `Usage: syncf <peers file> <listen address>` (`syncf` typo, see §T.22).
- file: `<peers file>` — 1 address per line, form `tcp://host:port`, line ≤ 512 chars. opened read-only ∴ ⊥ write permission needed (V32).
- arg: `<listen address>` — `host:port`. ZMQ PUB binds `tcp://<listen address>`.
- net: SUB connects ∀ peer & self. Subscribes prefixes `create`, `remove`, `state` broadcast, & `digest\0<own endpoint>\0` addressed (§V.58). Self-subscription ! stay, for 2 reasons now: `repairs.announcements` fills at the 1 site ∀ applied create passes (`src/syncfs.cpp:376`) ∴ ⊥ self-subscription = ⊥ repair cache; & cancel-on-observe (§V.59) still reads peers' repairs. §V.43's suppression reason is retired (§V.51).
- net: libtorrent listens `0.0.0.0:<port+2000>`. `ut_pex` extension on. Peer discovery = DHT + LSD + PEX, ⊥ tracker.
- wire: multipart. part0 = verb, | `<verb>\0<target endpoint>\0` for an addressed verb (§V.58) ∴ dispatch ! split part0 on NUL, ⊥ compare it whole. part count fixed per verb, ⊥ a blanket 2 (§V.3). Reconcile verbs (`state`, `digest`) carry a sender address, at the part each names below; data verbs (`create`, `remove`) carry ⊥ sender, & ! keep carrying none — §C's tie-break is computable from the message alone only while that holds. ∀ time = `system_clock` ticks, decimal int64 — `file_time_type` epoch is implementation-defined ∴ ⊥ portable.
  - `create` → 4 parts. part1 = bencoded torrent, v2-only, 1 file, piece length 0 ∴ libtorrent auto-picks, sender libtorrent endpoint embedded as DHT node. part2 = origin mtime. part3 = relative path in `files::list` key form (`./a/f`) — §T.21's fix, landed in the same break (§T.44) ∴ the count is 4 from the start, ⊥ 3-then-4. mtime rides beside the torrent, ⊥ inside it — `create_torrent::modification_time` folds it into the info dict & changes the info hash ∴ identical content would hash differently per node (§R.13, §V.45). A repair reuses this verb & shape verbatim, broadcast (§V.60) — `Source::repair` (`src/source.cpp:72-80`) already publishes `create` ∴ ⊥ a `repair` verb exists | is needed.
  - `remove` → 3 parts. part1 = file path. part2 = delete time.
  - `state` → 3 parts. part1 = list of SHA-256 hashes over the canonical form (§V.46), length 1 today — stays @ part1 ∴ the hash compare (`src/syncfs.cpp:339`) ⊥ move. part2 = sender address, form `tcp://host:port` (same as peers file). Published broadcast per §C quiescence gate — 32 B ∴ ⊥ worth addressing. Sender ! be there: §V.56's digest is addressed back to whoever's hash mismatched, & a `state` naming no sender ⊥ answerable.
  - `digest` → 4 parts, part0 addressed `digest\0<target endpoint>\0` (§V.58). part1 = sender address, form `tcp://host:port` (same as peers file) — now the reply address the repair & the next round's digest go to, ⊥ only the self-filter it was (`src/syncfs.cpp:344`, dead once ⊥ node addresses itself). part2 = held set. part3 = tombstone set. Set encoding: NUL-framed, same shape as §V.46's canonical form — ∀ entry `path\0ticks\0`, ticks decimal. ⊥ `\n`/`\t` framing: POSIX filenames exclude only `/` & NUL ∴ a name holding a tab or newline misparses into phantom paths → phantom gaps → permanent repair traffic for files that ⊥ exist (§V.22 already treats hostile names as real). Paths in `files::list` key form (`./a/f`). Published on `state` hash mismatch, to 1 peer chosen per §V.59. `?` 1 message vs chunked @ thousands of paths still unresolved — §V.40 hwm counts messages, ⊥ bytes ∴ the existing ceiling says nothing here. §V.56 cuts the round's total from O(N·M) to O(M), ⊥ the single message's size.
- log: spdlog. `NDEBUG` → level `info`, pattern `[%Y-%m-%d %T] [%P] [%^%l%$] %v`. else level `debug`, `%T.%F`.
- stats: torrent table `Name Progr Total Seeds Peers State` @ `debug`, every 2 s.
- sig: `SIGTERM` & `SIGINT` → sync loop ends, `"Stopping."` @ `info`, `EXIT_SUCCESS` (V33).
- test: ctest names `utils-unit`, `source-unit`, `monitor-unit`, `protocol-unit`, `syncfs-integration`, `syncfs-performance`. `make {config,build,test,test-unit,test-integration,test-perfomance}` wrap them in podman (`test-perfomance` typo is the real target name).
